# Security guarantees — what is claimed, and what is not

This document separates properties by the strength of the evidence
behind them. The language is deliberately bounded: detection-based
properties hold *for detected entities*, not for all PII.

## 1. Properties demonstrated by automated tests

Each item is enforced by at least one test in `tests/`; the test files
are named alongside.

* **Provider-boundary mediation.** For entity values detected by the
  configured recognisers and assigned tokenise, redact, or block
  policies, the tested provider-boundary cases did not contain the
  original fixture values (`tests/security/test_leakage.py`,
  `tests/security/test_policy_actions.py`).
* **Request-level tokenization.** Distinct detected values never share
  a placeholder within a request; repeated values reuse one; mappings
  never cross requests; rehydration replaces only exact whole tokens
  minted by the same request — forged, partial, unknown, and
  foreign-request tokens pass through unchanged
  (`tests/unit/test_tokenization.py`,
  `tests/integration/test_gateway_api.py`).
* **BLOCK means no provider contact.** Requests containing a detected
  BLOCK-policy entity produce zero provider calls and an HTTP 400 that
  names only entity types (`tests/security/test_policy_actions.py`).
* **Allowed entities are recorded.** ALLOW detections appear in audit
  decisions, distinguishing "no PII detected" from "PII detected and
  deliberately allowed" (`tests/security/test_policy_actions.py`).
* **Privacy-minimised audit records.** Default records contain no
  prompts, no responses, no token mappings, and none of the fixture PII
  values — including PII generated by the provider or embedded in
  provider exceptions (`tests/security/test_leakage.py`).
* **Fail-closed mediation.** A crashing detector or sanitizer results
  in zero provider calls and a safe error
  (`tests/security/test_fail_closed.py`).
* **Audit tamper evidence.** Content edits, timestamp edits, prev-hash
  edits, interior deletion, reordering, duplication, and re-hashing
  without the key are each detected at the correct record, with
  `entries_checked` reporting the number actually examined
  (`tests/unit/test_audit_logger.py`).
* **Tail-deletion honesty.** Tail deletion, complete deletion, and
  rollback are *not* reported as internal failures; with an external
  checkpoint they are detected (`tests/unit/test_audit_logger.py`).
* **Concurrency safety.** Concurrent appends from multiple logger
  instances and threads lose no writes, duplicate no ids, and fork no
  chains (`tests/security/test_audit_concurrency.py`).
* **Startup refusals.** Production with a missing/short/development
  HMAC key, or a provider without its API key, refuses to start
  (`tests/unit/test_config.py`).
* **Admin gating.** Audit endpoints are disabled without a configured
  admin key and reject bad credentials via constant-time comparison
  (`tests/security/test_admin_auth.py`).
* **Strict API scope.** Unknown fields, streaming, tools, non-text
  content, invalid roles, and oversized requests are rejected; the
  validation error does not echo submitted values
  (`tests/integration/test_gateway_api.py`).

## 2. Properties dependent on configuration

* Production-strength audit MACs require a strong, secret
  `GATEWAY_AUDIT_HMAC_KEY` (enforced ≥32 chars in production only).
* Tail-deletion/rollback detection requires `GATEWAY_AUDIT_CHECKPOINT`
  and a checkpoint location the DB attacker cannot rewrite.
* Response-side PII redaction requires `GATEWAY_RESPONSE_SCAN=true`.
* Audit endpoint availability requires `GATEWAY_ADMIN_API_KEY`.
* Log safety assumes the shipped safe-logging configuration; explicitly
  re-enabling DEBUG on `presidio-analyzer`/`presidio-anonymizer`, or
  adding new content-logging dependencies, steps outside the tested
  guarantee.

## 3. Known limitations

* **Detection is statistical.** False negatives forward raw PII under
  no policy at all; false positives may tokenize/redact/block benign
  text. Rates must be measured per deployment corpus
  (see EVALUATION_GUIDE.md).
* Redacted-content research mode stores text whose *detected* entities
  were removed; undetected sensitive content may remain. It is off by
  default.
* Checkpoint protection is bounded by checkpoint freshness and storage
  trust.
* English text only; single-host SQLite deployment.

## 4. Properties NOT provided

To avoid any ambiguity, this system does **not** claim:

* that all PII is detected;
* that raw PII can never reach a provider (only that *detected* PII
  under mediating policies did not, in the tested cases);
* that every deletion of audit data is detected (internal verification
  cannot see tail deletion, complete deletion, or rollback);
* that HMAC provides digital signatures, public verifiability, or
  non-repudiation — anyone holding the shared key can produce valid
  MACs;
* that the gateway supports every provider or the full OpenAI API;
* that the system is production-ready.
